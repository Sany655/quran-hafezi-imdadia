## A.2 Calculation engine

Formula:

\\[ DailyTarget = \frac{RemainingPages}{RemainingDays} \\]

For example, if 600 pages remain and the user selects 30 days:

- Daily target = 20 pages.
- Four sessions = 5 pages each.
- Expected completion = target date.

The app should also support two different planning methods:

1. Goal-based: User chooses finish date; app calculates daily requirement.
2. Capacity-based: User chooses pages per day; app estimates completion date.

If the user changes their target, future plans recalculate, but historical completed records must remain unchanged.

### B.2 Memorization lifecycle

This is where I would make your app different from a basic Hifz tracker.

A Quran portion should have a memorization status independent of its daily task status.

## Memorization lifecycle

1. Not memorized

   Portion is still ahead of the student's memorization boundary.
2. Learning — Sabaq

   Currently learning a new portion.
3. Recently memorized — Sabqi

   Newly learned material undergoing repeated revision.
4. Established — Manzil eligible

   Teacher-approved or student-confirmed memorization, ready for the older revision rotation.
5. Needs reinforcement

   A portion that has become weak and needs extra revision.

These are app-level states. Teacher approval and actual recitation quality should determine progression, not just elapsed days.

A very important rule: calendar automatically change kore Sabaq-ke Manzil baniye fela jabe na. Student jodi ekhono portion properly memorize na kore, tahole seta recent revision-e ba reinforcement-e thakbe.

### B.5 Automatic daily schedule generation

I recommend this algorithm:

1. Generate today's Sabaq from the current learning position.
2. Retrieve eligible recent lessons according to the configured Sabqi rule.
3. Retrieve the next due portion from the Manzil rotation.
4. Check for overlap.
5. Produce today's task list.
6. Let the student or teacher modify today's assignments.
7. Save the actual completed ranges separately.

Overlap prevention: A portion should not accidentally be counted twice in the same revision layer. However, a teacher may intentionally assign the same portion in two different sessions.

### B.6 Recitation assessment

This is an essential feature.

After every revision, student should be able to record:

- Perfect / no significant mistake.
- Minor hesitation.
- Multiple mistakes.
- Needed assistance.
- Needs repeat revision.

Also provide optional mistake categories:

- Missed Ayah.
- Word substitution.
- Hesitation.
- Ayah sequence confusion.
- Tajweed correction.

Keep teacher feedback optional. The app must never claim that it can independently verify Hifz accuracy simply because a user marked a task completed.

### B.7 Weekly Hifz review

Every week, show:

| Metric             | What it tells                                 |
| ------------------ | --------------------------------------------- |
| New memorization   | How much new material was learned             |
| Sabqi completion   | Whether recent memorization is being retained |
| Manzil completion  | Whether older Quran is being maintained       |
| Weak portions      | What needs extra attention                    |
| Teacher assessment | Whether progress is satisfactory              |

One particularly useful feature: a weekly review can recommend reducing new Sabaq when revision is repeatedly unfinished or weak. It should suggest, not force, a new target.

## C.1 Core concept: Daur management

A Hafez should be able to create a revision cycle:

- 7-day cycle.
- 10-day cycle.
- 15-day cycle.
- 30-day cycle.
- Custom cycle.

These are planning options, not universal requirements. The appropriate daily workload depends on the person's ability, time and current retention.

For a complete Hafez:

\\[ DailyTarget=\frac{30\ Juz}{CycleDays} \\]

Examples:

| Cycle   | Average daily target |
| ------- | -------------------- |
| 7 days  | 4.29 Juz             |
| 10 days | 3 Juz                |
| 15 days | 2 Juz                |
| 30 days | 1 Juz                |

This is a mathematical distribution, not a recommendation that every Hafez should follow the seven-day schedule.

## C.4 Weak portion management

This is a feature I strongly recommend.

Hafez can bookmark a Quran range as:

- Weak.
- Needs revision.
- Frequently forgotten.
- Recently strengthened.

When a weak range is added:

1. It enters the reinforcement queue.
2. It receives a suggested revision date.
3. It can be assigned an additional session.
4. After successful revision, user records its condition.
5. It remains in the overall Daur rotation regardless.

Never remove weak portions from normal Daur. Extra revision should supplement the full Quran cycle, not replace it.

- Teacher or listener assessment.
- Custom Surah revision collections.

## 6. Flutter + SQLite architecture

Since you explicitly want independent structures, don't force all three modes into a universal planner table.

I recommend separate domain models.

| Domain | Main records                                                       |
| ------ | ------------------------------------------------------------------ |
| Reader | Reading plans, sessions, daily logs                                |
| Hafezi | Memorization inventory, lessons, revision assignments, assessments |
| Hafez  | Memorized inventory, Daur cycles, revision logs, weak portions     |
| Shared | Reminder preferences, routine configuration, app settings          |

### Important data separation

There are three different concepts:

1. Planned activity — what the user intended to do.
2. Actual activity — what the user really completed.
3. Quran knowledge state — what the user has memorized and how well it is retained.

These must not be confused.

For example, completing today's Sabqi task doesn't necessarily mean the corresponding Quran range has achieved established memorization status.

### Offline calculation strategy

- SQLite is the single source of truth.
- Calculate daily tasks from persisted plans and progress.
- Cache expensive dashboard summaries if necessary.
- Rebuild analytics from actual activity records.
- Use local notifications; no server dependency.
- Rescheduling must update future notifications.
- Preserve completed historical records when plans change.
- Keep all Quran references anchored to Surah/Ayah ranges, with page numbers derived from the selected Mushaf.
